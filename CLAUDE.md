## Про проект

`cip_gov_ua_getter` — консольна утиліта для збору розпоряджень про блокування доменів
із `cip.gov.ua` (НЦУ), `webportal.nrada.gov.ua` (сервіси держави-агресора) та
`nkek.gov.ua` (рішення НКЕК). На виході — `blocked.result.txt` зі списком доменів
для блокування на рівні DNS.

Утиліта потрібна провайдерам для виконання розпорядження НКРЗІ про щоденний
моніторинг розпоряджень НЦУ.

**Кожен коміт із змінами коду повинен містити також:**

1. **`pom.xml`** — оновлену версію відповідно до Semantic Versioning:
   - нова фіча → мінорний реліз (1.17.x → 1.18.0)
   - виправлення / дрібне покращення → патч (1.17.0 → 1.17.1)
   - зламна зміна → мажорний реліз (1.x.y → 2.0.0)

2. **`CHANGELOG.md`** — новий розділ `## [X.Y.Z] — YYYY-MM-DD` з описом усіх змін
   (підрозділи: `### Додано`, `### Змінено`, `### Виправлено`)

## Збірка та запуск

```bash
mvn clean package                                  # збірка uber-JAR
java -jar target/cip_gov_ua_getter-3.2.1-all.jar   # звичайний запуск
java -jar target/cip_gov_ua_getter-3.2.1-all.jar -d # дебаг-режим
```

Конфігурація — `cip.gov.ua.properties` у корені (шлях можна передати аргументом).
Логи — `logs/cip_gov_ua_getter.log`, налаштування у `src/main/resources/logback.xml`.

Тестів немає. Перевірка змін — реальний запуск і аналіз логів.

## Архітектура

Потік даних лінійний, точка входу — `Cip_gov_ua_getter.main()`:

1. `BlockedObjects.getBlockedDomainNames()` — читає базові списки доменів із файлів (`blocked`).
2. `CGUGetter` — через Playwright тягне JSON зі списком розпоряджень з API `cip.gov.ua`.
3. `ParseCGUArticlesJson` — дістає масив `posts`.
4. Для кожного поста: фільтр за `ban_keywords`/`unban_keywords` → для кожного вкладення
   `GetPrescript` завантажує/читає файл і валідує домени.
5. `AggressorServicesParser` (наслідує `AbstractPDFParser`) — парсить PDF з `nrada.gov.ua`.
6. `PlaycityParser` (наслідує `AbstractPDFParser`) — парсить PDF НКЕК за списком `urlPdfs`.
7. `BlockedObjects.storeState()` — атомарно пише результат.

Уся валідація доменів зосереджена в `DomainValidatorUtil.validateDomain()` — спільній
для текстових розпоряджень і PDF.

## Ключові принципи, які треба зберігати

**Playwright, а не HTTP-клієнт.** `cip.gov.ua` має анти-бот захист; звичайний
`HttpURLConnection` отримує відмову. Тому запити йдуть через headless Chrome.
Не замінювати на простий HTTP-клієнт.

**Без паралелізації запитів до cip.gov.ua.** Між зверненнями стоїть пауза 1–2 с
(`Cip_gov_ua_getter`, після `!gp.isLocalRead()`). Паралельні запити ризикують
призвести до блокування. Паралелити можна лише локальну обробку (розбір PDF,
валідацію) або завантаження з інших доменів.

**Кешування обов'язкове — але не завжди назавжди.** Вкладення розпоряджень
(`store_prescript_to`) і рішення НКЕК (`PlaycityParser`) — незмінні історичні
документи за унікальним ID/URL; їх кешування назавжди коректне, не ламати
перевірку `isExists()`. Перелік сервісів держави-агресора (`AggressorServicesParser`) —
принципово інший випадок: сайт nrada.gov.ua перевидає «поточний стан» під
новим іменем файлу, а локальний кеш зберігається під одним фіксованим
іменем. Тому там кеш має термін придатності (`AggressorServices_max_age_hours`,
типово 24 год) через `downloadPdf(..., Duration maxAge)`: застарілий файл
намагається оновитися щоразу, а якщо сервер недоступний — використовується
наявна застаріла копія (WARN у лог), а не провал джерела. Без цього
розмежування перелік роками не оновлювався б, ігноруючи все, що nrada
публікує після першого успішного завантаження.

**Стійкість важливіша за швидке падіння.** Збій одного розпорядження, парсера чи
PDF не має зупиняти весь запуск: кожен блок обгорнуто в `try-catch`, помилки
пишуться у лог і `failed_ids.txt`, а `bo.storeState()` викликається завжди.

**Атомарний запис.** `blocked.result.txt` і завантажені PDF пишуться через
тимчасовий файл + `Files.move(ATOMIC_MOVE)` з фолбеком на `REPLACE_EXISTING`.
Не повертатися до прямого запису в цільовий файл.

**SSL — тільки per-connection.** `webportal.nrada.gov.ua` має некоректний ланцюжок
сертифікатів. Обхід реалізовано через `createTrustAllSslSocketFactory()`, що
застосовується лише до конкретного з'єднання після `SSLException`. **Ніколи** не
повертати глобальний `HttpsURLConnection.setDefaultSSLSocketFactory()`.

## Конфігурація

Ключові властивості `cip.gov.ua.properties`:

| Властивість | Призначення |
|---|---|
| `urlArticles` | API зі списком розпоряджень |
| `urlPrescript` | Префікс URL для завантаження вкладення (додається `id`) |
| `blocked` | Вхідні файли з доменами, через `;` |
| `blocked_result` | Вихідний файл |
| `store_prescript_to` | Кеш вкладень |
| `urlAggressorServices` | Сторінка з переліком сервісів агресора |
| `AggressorServices_max_age_hours` | Термін придатності кешу PDF агресора, у годинах (типово 24) |
| `urlPdfs` | PDF НКЕК: прямі URL через кому **або** `file:/шлях/до/списку` |
| `ban_keywords` / `unban_keywords` | Регулярні вирази через `\|` для фільтра постів |
| `max_file_size_bytes` | Ліміт розміру вкладення |

Файл читається як UTF-8 через `InputStreamReader`, але кирилиця може бути збережена
IDE як `\uXXXX` — обидва варіанти працюють.

Для `urlPdfs` із префіксом `file:`: у файлі один URL на рядок, рядки з `#` —
коментарі, `~` розгортається в домашню директорію. Відсутній файл → `WARN`, не падіння.
